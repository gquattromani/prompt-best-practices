## [0.10.0]

Source refresh. Every tracked vendor shipped a new generation after 0.9.0 — Claude Opus 5.5 and Claude Fable 5.1 / Mythos 5.1, OpenAI GPT-6 (Astra, Sol, Luna), Google Gemini 3.8 Flash, xAI Grok 4.7 — and several of them invert a rule the skill applied. Opus 5.5 defaults to `medium` effort and cannot run with thinking disabled. Fable 5.1 formats less and writes fewer progress updates than the models the anti-formatting and anti-narration rules were written for. GPT-6 asks more questions, delegates less, and tests more than GPT-5.6. Gemini now says to remove sampling parameters instead of keeping their defaults. The full `maintenance.md` procedure was run against the live pages of all four vendors and against the host map, and every double-quoted passage in the reference files was checked mechanically against the downloaded pages.

The release also ships the licensing and attribution pass prepared after 0.9.0, listed after the source-refresh items in each section. Apart from the accuracy corrections it lists, that part changes no behavior: it is the paperwork a redistributor, a marketplace reviewer, or a vendor's legal team would actually read, and it changed because the previous version overstated what the project could grant and what it had verified.

## [0.9.0]

Activation fix. The skill worked when invoked and rarely fired on its own — in practice you had to type `/prompt-best-practices` every time. That is not a tuning problem, it is a structural one, and it has three causes worth naming because they generalize to any skill that interrupts rather than assists.

**One:** before a skill is loaded, an agent sees only its frontmatter `description`. The entire `### AUTO-ACTIVATE when…` contract lives inside `SKILL.md`, which is read *after* the skill has been chosen — so the rules written to govern activation could never participate in the decision to activate. **Two:** the `description` spent most of its budget on mechanism (three tiers, fast-track, fixtures) and on exclusions, and negative clauses bias a reader toward not acting. **Three:** activating means interrupting an execution request to ask a question, against an agent whose default drive is to execute; with nothing in context to resolve that tension, it resolves toward executing.

The ironic consequence: instruction-tier hosts (Cursor, Windsurf, Kiro, Copilot in the editor) behaved *better* than Claude Code, because they read `AGENTS.md` on every turn and therefore had the contract in context. The 0.7.0 decision to ship no hooks — correct about there being no mode to inject — missed that the activation rule itself is what needs injecting.

## [0.8.0]

Runtime-aware composition. Until now the skill had one prompting dialect with a Claude bias and a Codex annex: it asked which *model* the user was targeting and defaulted to Claude Opus 5 when nobody said. That was defensible when it shipped for Claude Code alone. With adapters for two dozen hosts (0.7.0), it became wrong — a prompt built in Gemini CLI was being written in XML with a Claude-shaped verbosity assumption, and a prompt built in Grok Build was being trimmed by a rule xAI explicitly contradicts.

The skill now resolves the **runtime** before it composes anything: an explicitly named model wins, otherwise the host decides (Claude Code → Anthropic, Codex → OpenAI, Gemini CLI / Antigravity / Jules → Google, Grok Build → xAI), otherwise it builds to a vendor-agnostic baseline and says so. Two design choices are worth stating because they are what keeps this from rotting: routing is **not** a dialogue question (it never consumes one of the tier-capped questions), and a multi-model host resolves to the baseline rather than to a guess.

The uncomfortable finding is that the vendors do not merely differ in syntax — they invert each other. Three ask for leaner prompts; **xAI asks for a thorough system prompt with edge cases spelled out**. Anthropic and OpenAI replace "think hard" with a parameter; **Google explicitly endorses "Think very hard before answering" on heavy-reasoning tasks**. Anthropic wants a self-check clause deleted on Opus 5 and kept on Fable 5; Google wants no verification clause at all and Search grounding instead. Averaging those into one house style would have produced a prompt that is mediocre everywhere, so each conflict is recorded in an explicit divergence table and the baseline deliberately omits every contested item.

## [0.7.0]

Portability pass. **No prompting guidance changed in this release** — the 7 components, the tier thresholds, the dialogue caps, the activation rules, the rubric marks, and every per-model gate are byte-for-byte the 0.6.0 content. What changed is *how many agents can load them*: the skill was installable as a Claude Code plugin or through `skills.sh`, and every other platform was left to figure out `skills/` on its own.

The repository now ships a thin adapter per host: a manifest where the host installs plugins, a slash command where it reads commands, and a compact always-on rule where it only reads project instructions. Two support tiers are made explicit — plugin-tier hosts get the skill plus `/prompt-best-practices`, instruction-tier hosts get the activation contract, tiers, components, and dialogue caps without the reference set.

The failure mode this introduces is drift: eight copies of the same rule text and nine manifests that must agree on a version and on paths. Fixture set G exists for exactly that, and the copies are generated from one canonical body rather than hand-maintained.
